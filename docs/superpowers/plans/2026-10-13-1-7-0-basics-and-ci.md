# befui 1.7.0 (missing basics and a CI gate) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship eight new core components, a vitest + axe accessibility gate over every example, a CI workflow, and a README catalog generated from the registry, as release 1.7.0.

**Architecture:** Each component is the usual three files (`src/components/ui/<slug>.tsx`, `src/examples/<slug>.tsx`, one `m(...)` line in `src/registry/index.ts`); `npm run registry:build` generates everything downstream. Tests run in jsdom: one file renders every example and runs axe against a shrink-only baseline, one file tests the eight new components in their open states.

**Tech Stack:** React 19, Tailwind 4, Radix, TypeScript strict, Vite 6, vitest 3, jsdom, @testing-library/react, vitest-axe, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-13-1-7-0-basics-and-ci-design.md`

## Global Constraints

- Every new component: one file; `cn` from `@/lib/utils` for classes; `cva` for variants; logical start/end spacing (`ms-`, `ps-`, `start-`, `rounded-s-`, `border-s`, never `ml-`, `pl-`, `left-`, `rounded-l`, `border-l`) so it flips in RTL; motion disabled under `prefers-reduced-motion` (the global CSS rule covers CSS animation; JS-driven motion must check `matchMedia`); a typed props interface with a one-line doc comment; enter animation is the existing `animate-pop`, no new keyframes.
- Registry: any change under `src/components/ui`, `src/examples`, `src/registry/index.ts` or `scripts/build-registry.mjs` is followed by `npm run registry:build`, and the regenerated `public/`, `src/registry/requires.json`, `README.md` and `CHANGELOG.md` are committed with it.
- Tests: vitest 3.x (matches Vite 6), environment jsdom, explicit `import { ... } from 'vitest'` (no globals), accessibility asserted as `expect((await axe(node)).violations).toEqual([])`, axe `color-contrast` rule off. CI runs Node 22.
- New packages: `@radix-ui/react-hover-card`, `@radix-ui/react-navigation-menu`, `@radix-ui/react-menubar`, `qrcode-generator` (MIT, no dependencies, ships types; confirmed with `npm view`). `@radix-ui/react-toggle-group` and `@radix-ui/react-popover` are already installed.
- After each task: `npm run registry:build && npm run typecheck && npm test` pass, then commit and `git push origin main`. Never force-push.
- Out of scope: npm publishing, fixes to existing components beyond baselining, new chart types, Playwright, lint, scanning blocks, any change to `segmented`.

## Review Focus

Failure modes the spec implies but never states; each has a pinned test in the task named.

1. `QRCode` with `value=""` renders nothing, not an empty or broken SVG (Task 10).
2. `QRCode` with text too long for any QR version renders nothing instead of throwing, and non-Latin1 text (emoji) is encoded as UTF-8 (Task 10).
3. `Tour` with no steps, with every target missing, or whose target disappears mid-tour never throws and never leaves the dim overlay behind (Task 9).
4. `Tour` under reduced motion scrolls its target with `behavior: 'auto'`, not `'smooth'` (Task 9).
5. Physical-direction Tailwind classes sneaking into any new file, which breaks RTL (Task 4, scans all eight files).
